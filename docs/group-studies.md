# Private Group Studies

Collaboration owns Group Study organization: name, purpose, lifecycle and immutable history. Space remains the authority for registered active PRIVATE Group membership. OWNER creates/edits/transitions/archives; MEMBER and VIEWER read current/archived studies and history. Every request obtains a fresh Space participation grant and matches its Space ID to ACTIVE Collaboration configuration. No roles or actors are accepted from browser input.

Create starts PLANNED. Operational transitions are PLANNED → ACTIVE → COMPLETED, with archive to RETIRED from any non-archived state. Completed Study metadata may be corrected; archived studies cannot be edited or reopened in this slice. These are Group operational states, separate from individual Learning progress/completion. No personal Note, roadmap, StudySession, evidence, file or progress is read or copied. Study-to-roadmap/Course/Assignment/Discussion/Submission relationships are subsequent slices.

`/api/groups/{groupId}/studies` supports POST and bounded UUID keyset GET (default20/max100). Detail supports GET, metadata PUT and archive DELETE; `/state` PUT accepts ACTIVE/COMPLETED; `/revisions` GET is descending, bounded default5/max10 with nextBefore. All mutation bodies are strict JSON <=65536 bytes; name is nonblank <=200 code points without controls, description <=32768 UTF-8 bytes with valid Unicode and no NUL. GET/DELETE require empty bodies. Writes require exact HTTPS Origin and same-origin Fetch metadata when present; browser credentials must be singleton. All responses are no-store.

Creation requires a 32-hex Idempotency-Key, scoped to Group/creator/key. Immutable original name/description are stored separately from editable state. Same-key changed original input returns409; exact retry returns the current snapshot, including after edit/archive, without duplicate/reopened aggregate, revision or event. Root Group locking serializes concurrent creation. Metadata/state/archive use strong If-Match `"stN"` (missing428, stale412). Same-value operations with current version return the existing snapshot without extra event. Backward/skipped lifecycle transitions and archived edits return409.

Collaboration migration V2 adds Group Study and revision tables; composite Group/Space FK stays inside Collaboration. UUIDv7 IDs belong to Collaboration. Current row, immutable revision and full Protobuf snapshot Outbox commit atomically. Existing `collaboration-outbox` routes to `collaboration.study.v1`, Registry `collaboration/study-events/1`. Only Connect receives topic producer permission, and the Group validator receives read permission. Existing published contracts, offsets, slot and publication remain unchanged. Future consumers must deduplicate stable eventId and apply increasing aggregate versions.

Group page supports owner creation with uncertain-reply retry, metadata edit, lifecycle and archive; every active member can open current/archived snapshots and page through their immutable histories. Private state stays in memory, is cleared on hidden tab/access denial, and in-flight requests abort on unmount. Frontend remains the agreed functional prototype.
