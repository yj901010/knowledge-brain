# Study reference roadmaps

Each Group Study may explicitly select one current Group shared roadmap as its learning reference. Collaboration owns only the relationship and immutable reference provenance (Learning link ID/version, original public roadmap Space/ID/version and title observed at connection). Learning owns the Group link and pinned graph. No graph, personal progress, StudySession, Note, evidence or attachment is copied or published. No cross-service SQL, FK or distributed transaction is introduced.

Registered active OWNER can connect, replace, unlink and explicitly reconnect until the Study is archived. MEMBER and VIEWER read the relationship/history and open the Learning graph through existing permission-checked APIs. Archived Study relationships remain readable and cannot be changed. These bindings have their own versions, independent of Study operational state/metadata versions.

GET `/api/groups/{groupId}/studies/{studyId}/roadmap` returns `{binding:null}` with strong `"sr0"` when absent. PUT accepts exactly roadmapLinkId and roadmapLinkVersion, <=2048-byte JSON, with If-Match `"srN"` including sr0. DELETE requires an empty body and current sr version. Missing precondition428, stale412. The same current reference/current version and already-unlinked DELETE are no-ops. A replacement/unlink/relink increments the same binding aggregate and records an immutable revision and Outbox snapshot atomically. After uncertain replies refresh GET to recover the committed result; stale conditional requests are not silently retried. `/revisions?before&limit` is descending, default5/max10 keyset history. HTTPS exact Origin, singleton credentials, strict bounded bodies/queries, UUIDv7, no-store and trace context apply.

Collaboration freshly resolves Group membership and ACTIVE own Group configuration, checks Study scope and pre-archive state, then calls Learning's dedicated reference capability with the same opaque browser token in a redacted body and traceparent. The capability is secure singleton constant-time bearer-only; browser Cookie/Origin and query parameters are rejected. Learning freshly authorizes the same Group Space and returns only link/provenance metadata. Collaboration checks identity, Space, link, ACTIVE state and observed version. The fixed HTTPS client validates the configured public CA and hostname, denies redirects, has3s connect/5s read deadlines and strict <=16KiB JSON responses. Source unavailable/stale/retired/foreign or mismatched principal never writes a relationship.

Source validation is a point-in-time read before the local write. A Group roadmap may retire between validation and commit; the saved reference remains auditable. Reading the Learning graph shows its current Group-link state, including retirement. It is never automatically detached or rewritten, and public source revisions never silently change the selected pinned version. Study retirement and binding writes share local Group/Study locks, so archival is rechecked at commit. No network call is made while holding that database transaction.

Collaboration migration V3 owns binding and revision tables with only own Study/Group/Space composite FKs. Learning IDs remain external references. Existing Study/Group schemas and published contracts are not rewritten. New self-contained `collaboration/study-roadmap-events/1` Protobuf snapshots publish through the existing Outbox connector to `collaboration.study-roadmap.v1`. Events contain only relationship/provenance, actor, Space, trace and stable eventId. Future consumers deduplicate eventId and apply increasing binding versions. No new projector is included in this slice.

The Study detail panel supports current reference, active Group-roadmap candidate pagination, graph preview with explicit confirmation, replace/unlink, current graph inspection (with retired-source notice), and paginated binding history. A separate refresh recovers uncertain commits. Inputs/private results stay in memory and abort/clear when hidden, unmounted or denied. The frontend remains the agreed functional prototype.

## Local operation

Run `scripts/Provision-LocalStudyRoadmap.py` to preserve the dedicated Learning/Collaboration capability Secret. Base and local Helm values use the same logical configuration and existing public CA mount. The Learning API NetworkPolicy additionally allows the Collaboration caller; no private CA key is mounted in either application. Internal reference routes are not exposed by Gateway. Both feature flags default disabled in application code.

Prepare Registry and new Kafka topic/producer/validator ACLs before canonical writers, retaining existing connectors, slots, publications and offsets. Run BackendValidation separately for Collaboration with --group-kafka, Learning with --learning-kafka, and Gateway. `Run-GraphWebValidation.py --study-roadmap --group-studies --group-membership --group-roadmaps` validates the new relationship and all previous Group slices using actual accounts. Build all three affected services, import exact images on both nodes, then roll out Learning, Collaboration and Gateway. Evidence: `.local/study-roadmap-validation.json` and `docs/study-roadmap-bindings-validation.txt`.
