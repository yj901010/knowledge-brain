# 속성값으로 노트 좁혀 보기

`/graph`의 **내 노트 목록 → 속성 탐색 열기 → 속성 선택**에서 값을 입력하고
**값 조건 적용**을 누른다. 문자열·숫자·참/거짓·날짜는 같은 값인 노트를,
문자열 목록은 입력한 항목 전체를 포함한 노트를 찾는다. 조건은 서버에서
전체 활성 노트에 적용한 뒤 20개씩 조회한다.

- 문자열은 공백·줄바꿈·대소문자를 그대로 비교한다. `%`, `_`도 문자 자체이다.
- 숫자는 소수 정밀도를 유지한다. `80`, `80.0`, `8e1`은 같은 조건이다.
- 참/거짓과 날짜는 전용 입력으로 선택한다.
- 빈 문자열도 검색할 수 있다. 목록의 빈 항목 검색은 빈 목록 검색과 다르다.
- 입력만 바꿔서는 현재 결과가 바뀌지 않는다. 적용된 조건을 별도로 표시하며,
  다음 페이지와 새로고침에도 그 조건을 유지한다. **값 조건 해제**는 전체 값으로 돌아간다.

조건은 최대 200 Unicode code point이다. 저장 가능한 STRING 최대 길이 1000자와
다르므로 200자를 넘는 문자열은 이번 정확 일치 필터로 찾을 수 없다.
[숫자·날짜 범위 조건](property-range.md)도 지원한다. 부분 일치·여러 속성 조합·
값별 정렬과 통합 검색 조건은 별도 확장이다.
속성 목록의 활성 노트 개수는 필터 적용 전 전체 개수이다. 페이지는 실시간 조회이며
고정된 snapshot이 아니다.

[태그 조건](property-tag.md)도 함께 적용할 수 있다. 태그와 값 조건은 각자 적용·해제하며
서로의 적용 상태를 유지한다.

잘못된 조건은 현재 결과를 유지한 채 입력 오류를 안내한다. 적용한 조건의 조회가
실패하거나 응답 값이 조건과 맞지 않으면 결과를 비우고 새로고침을 안내한다.
조건·속성 변경과 패널 닫기에서 이전 요청을 취소하고 늦은 응답을 버린다.
개인 공간 접근이 만료되면 기존 개인 화면 초기화 경로를 사용한다. 탐색은 독립적인
노트 편집 초안을 유지하며 브라우저 저장소나 도메인 데이터에 쓰지 않는다.

## API

`GET /api/spaces/{spaceId}/property-definitions/{propertyId}/notes`에 선택적 query
`value`를 추가한다. 생략하면 기존 전체 값 조회이며, `value=`는 빈 문자열 조건이다.
응답 형식과 `after` UUIDv7 커서, `limit` 기본 20·최대 100은 그대로이다.
다음 페이지에도 같은 `value`를 보내야 한다. 값은 UTF-8 URL encoding으로 전송한다.
`value`는 범위 조건 `minValue`/`maxValue`와 동시에 보낼 수 없다.

| 속성 타입 | value의 의미 |
| --- | --- |
| STRING | 정확히 같은 문자열 |
| NUMBER | JSON 숫자 문법의 정확한 십진수 동등 비교 |
| BOOLEAN | `true` 또는 `false` |
| DATE | 실제로 존재하는 `YYYY-MM-DD` 날짜 |
| STRING_LIST | 배열에 정확히 같은 문자열 항목이 포함됨 |

NUMBER는 기존 저장 값의 정밀도에 맞춰 정규화 후 유효숫자 최대 38자리,
소수부 최대 18자리, 정수부 최대 56자리를 허용한다. 원문은 최대 96자,
지수는 최대 3자리이며 정규화 후 경계를 다시 검증한다.
Gateway는 이 경로에서만 최대 2600자의 query를 허용하고 올바른 UTF-8, 200자 제한,
NUL 금지, 중복·알 수 없는 키 차단을 검사한다. Content는 현재 속성 타입에 맞는
조건을 검증한다. 잘못된 조건은 400이다.

매 페이지 Space 권한을 새로 확인하고 PRIVATE/ACTIVE Note만 반환한다. 타 Space나
없는 속성은 404이며, 알려진 속성의 일치하는 값이 없으면 빈 페이지이다. 정상 응답은
`Cache-Control: no-store`이다. 조회 본문과 쓰기 메서드는 허용하지 않는다.

## 소유권과 검증

AGENTS.md와 PROJECT.md의 결정과 충돌하지 않는다. Content 소유 PostgreSQL에서
scalar `jsonb =` 또는 목록 `jsonb @>` 조건을 바인딩하고, 커서와 LIMIT 전에 적용한다.
기존 V13 인덱스를 사용한다. 새 migration·의존성·이벤트 계약이나 정본 데이터 변환은 없다.
기존 HTTP/trace 관측과 `brain.content.metadata.reads{type=property_notes_filtered}`를
사용하며 값이나 도메인 ID를 metric label에 넣지 않는다.

실제 PostgreSQL/Kafka, Gateway, Next.js/TypeScript 및 로컬 Kubernetes 브라우저로
정밀한 숫자와 20+2 페이지, 다섯 타입, 빈 값, 조건 전환·해제, 입력 초안 유지,
잘못된 응답·늦은 응답, 타 Space 차단·접근 철회와 기존 탐색 회귀를 검증한다.
실행 결과는 [검증 기록](property-filter-validation.txt)에 기록한다.
