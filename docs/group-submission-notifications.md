# Group submission notifications

Approved on 2026-10-25: each registered participant explicitly enables their own Group subscription. Default is off, independently of existing personal reminder preferences. The inbox is private to the recipient, including against the Group OWNER. It contains only feedback changes, resubmission requests/cancellations and recorded/corrected grades on the recipient's own submissions. Self actions and automatic resubmission resolution produce no alert. Retraction/restoration streams are supported by the follow-up in `review-lifecycle-notifications.md`; mail and push remain separate.

Notification owns preferences, immutable preference revisions, durable receipt decisions, inbox items, immutable state revisions and Outbox. Collaboration owns all original answers, feedback, request reasons, grades and attachments. Notification never copies those contents, the original envelope or a signed object URL. Every displayed change records the source event/aggregate/version, submitted attempt and Study/Assignment/Submission IDs. Opening the original uses the existing Collaboration submission component and rechecks current permissions; it shows the current answer and its version history, clearly distinguishing it from the alert's pinned attempt.

Space supplies a dedicated TLS POST `/internal/space/group-review-authorization` capability resolving the common principal freshly and requiring REGISTERED, current ACTIVE private Group Space and current OWNER/MEMBER/VIEWER membership. It returns only Group/Space/current principal/membership version. No arbitrary recipient parameter. Notification receives no Collaboration owner capability. Every inbox/preference/history API call checks this capability. Disabling reception keeps previously delivered inbox records accessible. Membership changes invalidate effective consent and hide inbox entries from the previous membership version; re-enabling requires a new explicit action. Group removal denies all reads/writes. Old audit facts are retained privately.

Enabling records a millisecond cutoff strictly after the consent transaction's sampled time. Source events older than that cutoff are suppressed, regardless of delivery delay. Re-enabling does not backfill the disabled interval. Preference changes and first receipts serialize on an own-DB Group/recipient advisory lock. Receipts remain durable even when no inbox item is created, so replay cannot reinterpret a prior suppression. Inbox creation, revision and Outbox commit together before the Kafka offset acknowledgement. Same event with different original SHA256 or same source aggregate/version under another event ID fails closed and remains unacknowledged. Content is excluded from logs, metric labels and notifications.

The consumer reads exactly `collaboration.submission-feedback.v1`, `collaboration.resubmission-request.v1`, `collaboration.submission-grade.v1`. Only existing Connect writes Kafka. Original full source contracts remain unchanged. On first startup or an offset outside retention, the consumer captures assigned partition end offsets, reads bounded ordered content-free signals from Collaboration's own retained Outbox using a separate export credential, then seeks the captured offsets. Late commits/CDC overlap replay through the durable hash receipt. The export returns minimal metadata and the SHA256 of the original bytes, never the private content. Notification and Collaboration independently validate the published source schemas.

New event: `notification.group-review.v1`, Registry `notification/group-review-events/1`, `notification_group_review_v1.proto`. Dedicated new artifact; VALIDITY FULL, COMPATIBILITY FULL_TRANSITIVE. Exact literal topic ACLs; Notification is read-only on the three source streams, validator read-only on the new topic. No new dependencies, database privileges, cross-owner SQL, distributed transactions, changed old migrations/contracts, Kafka offset resets, publication/slot/PVC changes.

Public endpoints: `/api/groups/{groupId}/notification-preference` GET/PUT (`gnpN`, initial gnp0), `/revisions` GET; `/api/groups/{groupId}/notifications` GET, `/{notificationId}` GET/PUT/DELETE (`gnN`), and `/{notificationId}/revisions` GET. Strong If-Match, singleton exact Boolean JSON, TLS and same-origin writes, duplicate-cookie/query rejection, bounded page/history cursors, and no-store responses. Catalog cursors bind Group/Space/recipient/membership/filter. Read/archive are explicit, independent of the source. Revisions are immutable and paged. Uncertain browser writes freeze mutations until explicit refresh. Component state is memory-only and cleared on hidden/unmount/denial.

Operational readiness adds `groupReviewConsumer` alongside the existing reminder consumer. Fixed-label metrics: `brain.notification.group-review.events`, `.failures`, `.recovery`, `.changes`, `.reads`. Receipt/hash collision or canonical export outage keeps readiness down without skipping a record. Diagnose error class and source IDs through trace; never log answers/scores/opinions or credentials. Existing Personal reminder flow is unchanged.

Follow-up: version-pinned retraction/restoration alerts and explicit original event resolution are documented in `review-lifecycle-notifications.md`.
