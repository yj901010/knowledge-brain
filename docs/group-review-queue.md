# OWNER Group-wide feedback and request review queue

On /graph/groups, current OWNER opens Group -> 그룹 피드백·재제출 검토목록 열기. The collapsed memory-only queue spans submitted work in all canonical Studies/Assignments in the exact Group/Space, including standalone Studies without Course relationships. Existing OWNER own-submission feedback/request workflows remain included. The separate grading queue and writer still forbid self-grading. No non-submitter roster, profile lookup, Course/enrollment or private progress requirement. Fresh current registered Space OWNER authority and matching ACTIVE Collaboration Group configuration precede queue SQL on every request. MEMBER/VIEWER403 even for empty queues; removed participation loses access.

NEEDS_FEEDBACK default includes missing, older-answer, exact latest withdrawn or unavailable feedback. HAS_FEEDBACK requires known current-answer latest feedback with absent/restored annotation. RETRACTED_FEEDBACK includes exact latest withdrawn current/older-answer feedback, excluding unavailable feedback. Historical markers never mark newer comments. Independent PENDING_RESUBMISSION requires a request for the current answer without resolution. CANCELLED retains its source without resolution; RESOLVED requires requested < resolved <= current answer. Later answers retain first resolution; replayed old submission cannot resolve a newer request. Unknown/missing/inconsistent metadata becomes UNAVAILABLE, never current feedback or pending/resolved request. UNAVAILABLE includes either unsafe dimension; known current feedback may coexist with unavailable request. ALL includes every submitted row. Request resolution means new answer arrival, never grading, approval or learning completion.

Twenty metadata fields: Submission/author/source versions/time; feedback status/version/source, exact latest-version retraction state/version and needsFeedback; request version/state/source; current Assignment ID/title/state and Study ID/title/state. Original submitted instructions remain pinned. No answer, feedback text, request/retraction reason, score, reviewer identity, rubric or file copies. Independent queue refresh/filter preserve open feedback/request and Study edit drafts. Explicit selection freshly rechecks current Group OWNER and remounts existing exact original Study/Assignment/Submission controls, including same-Assignment author, cross-Assignment and cross-Study reselection. Source close, Group switch, hidden tab/unmount and authority loss clear the target. Owned and participating-OWNER entry points use the same workspace; MEMBER/VIEWER do not render it. Archived reads retain original confirmation/CAS and write restrictions.

GET /api/groups/{groupId}/submissions/review-queue accepts singleton filter/after/limit, canonical UUIDv7, empty GET body, default20/max100, registered secure singleton session and no-store. Local ACTIVE Group/Space check is followed by one canonical Study/Assignment/Submission/Feedback/exact feedback-version Retraction/Request metadata statement using full tenancy/source/author tuples. Source feedback and atomic request resolution share one snapshot. Existing Group/Study/Assignment catalog, Assignment-author, feedback-submission and marker/request keys are reused. Predicates precede limit+1 and ascending Submission UUID keyset. Pages are current reads; refresh begins at the start. No Course/curriculum/enrollment query or cross-owner SQL/FK.

UI validates exact twenty fields/enums, nullable versions, feedback classification/needs relationship, normalized request bounds, requested filter and bounded ordered cursor. Study states may differ across rows. Invalid/error responses clear rows/cursor with explicit retry and no false empty result. Hide/unmount aborts/clears; authority loss clears parent Group. No polling or persistent storage. Legacy per-Assignment review retains twelve fields, five filters and ALL default; UNAVAILABLE remains restricted to separate overview routes. Existing Group/Study/Course grading and review endpoints/writers remain unchanged.

No persistent ID/revision/Outbox, migration, published Proto, dependency/dataset, Course creation, enrollment, notification, unread tracking or private progress/sharing mutation. Fixed submission.reads type=group-review-queue and existing traces/pool/probes apply without private content logging. This packages existing OWNER submitted-work rights without restructuring service ownership or changing source policy.

OpenAPI: contracts/openapi/group-review-queue.yaml. API/Gateway tests cover fresh OWNER, strict roles/session/query/body/path and unchanged legacy filters. Browser proof covers actual feedback/request writes and resolution/replay, exact source reselection, Group switch/fresh role, drafts, recovery/privacy/mobile, both OWNER entry points and existing queue/source regressions.
