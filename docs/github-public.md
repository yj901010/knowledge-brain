# Public GitHub repository connections

Decision 2026-11-01, explicitly approved by the user: start with public repository browser URLs and explicit recent-commit sync. Private repositories, GitHub App registration and identity attribution are separate future work.

Registered accounts can open **GitHub 저장소 열기** in their selected PERSONAL/PRIVATE Space. Enter `https://github.com/owner/repository`, explicitly consent, connect, then choose **최근 커밋 가져오기**. Connecting alone never imports commits. The current default branch contributes at most20 recent observations per command; this is not a complete Git history or a contribution count. At20, the UI conservatively says older commits may exist. Empty repositories produce an empty successful observation. Explicit repeat sync records a new observation but imports no duplicate SHA. Imported author login is optional and does not prove the platform user's ownership or contribution. Import date drives Activity; Git commit date is displayed separately. Learning progress, grades and public knowledge are unchanged.

Integration Service owns connections, immutable imported commits, command receipts, revisions and Outbox in its own PostgreSQL database. Space supplies fresh registered OWNER authority before and after remote calls. No cross-service SQL or foreign keys. Persistent IDs are UUIDv7; external repository numeric ID and commit SHA remain external references. Active external ID is unique within each Space. A moved/rebound URL is rejected; the pinned external repository ID cannot silently change. Disconnect changes ACTIVE to RETIRED; old imports, revisions and Activity remain private and readable. Reconnection starts a new connection identity.

Browser session and Origin checks precede writes. ghrN strong If-Match protects sync/disconnect; connect and sync use caller-scoped32lowerhex idempotency keys. A matching retry uses the stored receipt before GitHub I/O, including after disconnect. Same key with different content/version is rejected. Writes and revisions/Outbox share one local ACID transaction. Lists use scoped UUID keysets; history uses descending version. Errors and private responses are no-store. Browser state is memory only and clears on Space change, close, logout and document hiding. A lost connect/sync response retains the exact intent for explicit retry.

Production code calls only fixed HTTPS api.github.com with redirects disabled, no Authorization/Cookie, bounded2MiB responses and one8-second total deadline per API call including response-body reads. Only public metadata and one commits page are read; no clone, source code, author/committer email fields, token or private repository content is stored. Subjects retain a bounded500-code-point first line. A403/429 returns503 without writes or automatic retry. Public unauthenticated GitHub access is subject to IP-wide rate limits; wait before retry. No new libraries, dependency versions or dataset redistribution are introduced. Public access is not a grant of repository-content redistribution rights; this feature stores limited private metadata references only.

Connect is the sole Kafka writer: integration.github-repository.v1 and integration.github-commit.v1 carry immutable Protobuf envelopes registered in Apicurio. Integration CDC can SELECT only Outbox and cannot connect to other owner databases. Activity reads only commit events using scoped TLS Kafka ACLs, its durable Inbox and ClickHouse projection. Recovery fixes Kafka offsets before scanning all five owners' retained Outbox APIs; migrationV10 requests warmup without deleting Inbox, offsets or source data. Duplicate delivery/replay remains idempotent. Integration's private canonical export has a separate service key and is never browser-routed.

Local setup: Provision-LocalIntegration.py; provision Integration CDC and scoped read validator; publish/validate both immutable contracts; upgrade brain-connect, wait for its mounted secret and RUNNING task, then configure only the integration-outbox connector. Deploy Space authority and Integration before Activity, then Gateway. Existing operators must run the updated Activity Kafka ACL provisioning. No PVC, cluster, slot, publication or offset reset is required. Observability uses brain.integration.github.commands, brain.integration.github.reads and brain.integration.activity.exports plus existing tracing/Activity lag/readiness.
