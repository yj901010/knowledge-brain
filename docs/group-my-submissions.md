# Group-wide own submissions and grading metadata

On /graph/groups, each current registered Group participant opens Group -> 그룹 내 제출·채점 현황 열기. The collapsed memory-only overview spans only the freshly authenticated actor submitted work across all canonical Studies in the exact Group/Space, independently of Course relationships, enrollment or private progress. Even OWNER receives only own work here; the separate OWNER grading/review queues retain their existing rights. VIEWER retains own reads and original write restrictions. Current Space participation and matching ACTIVE Collaboration Group configuration precede SQL on every request; revoked participation loses access.

ALL default; NEEDS_GRADING, MISSING, CURRENT, OUTDATED, RETRACTED, UNAVAILABLE retain existing Study/Course meanings. NEEDS_GRADING is every status except CURRENT. Direct/rubric0 are actual grades. Only the exact latest grade-version annotation applies; withdrawing an historical grade cannot invalidate a newer grade. Resubmission makes an older-answer grade OUTDATED, including a withdrawn old grade; RETRACTED filters only the current-answer withdrawn latest grade. Unknown/missing marker state or impossible newer-answer grade becomes UNAVAILABLE, never CURRENT. Grade metadata never means pass, obligation or private completion.

Fifteen fields: Submission ID/version/submitted Assignment version/update time, grading status/latest grade version/graded submission version/exact marker state/version, current Assignment ID/title/state and current Study ID/title/state. No author/peer roster/count, answer, score, reason, file, rubric or progress copies. Current labels preserve originally submitted instructions. DRAFT/CLOSED/RETIRED definitions retain existing source-read policy. Different Study lifecycle states may coexist in one page; Study completion state remains separate from private Learning completion.

GET /api/groups/{groupId}/my-submissions accepts singleton filter/after/limit, canonical UUIDv7, empty GET body, registered secure singleton session and no-store. Ascending Submission UUID keyset, default20/max100 and predicate-before-limit+1. One Collaboration-owned SQL statement joins Submission/Assignment/Study with full Group/Space/Study/Assignment tenancy and own author, plus the matching grade source/author and exact grade-version marker. Canonical source and metadata share a statement snapshot, including concurrent resubmission/grade updates. Existing local indexes are reused; no Course query or cross-owner SQL/FK.

Explicit selection rechecks current participation, then remounts exact original Study/Assignment source with the fresh OWNER flag. Original APIs supply private answer/grade/reason, original submitted instructions and current CAS/confirmation/idempotency/permission rules. Same-Study different-Assignment, cross-Study and repeat selection reload exact source. Refresh/filter preserve open answer and Study edit drafts. Source close, Group switch, hidden tab/unmount and authority loss clear target. Both owned and participating Group entry points use the same workspace. VIEWER cannot submit or access OWNER controls.

UI validates exact15 fields, IDs, bounded labels, lifecycle and grade enums, safe positive versions, nullable grade/marker tuple, exact derived grading status, requested filter and ordered bounded cursor. Invalid metadata/errors clear rows/cursor and require retry without false empty messages. No polling or persistent browser storage. No new persistent ID/revision/Outbox, migration, published Proto, dependency/dataset, Course creation, enrollment, unread tracking, notification or private progress/sharing changes. submission.reads type=group-mine and existing traces/pool/probes apply without private content logging. Existing endpoints, source writers and parents remain unchanged except new workspace import/panel.

OpenAPI: contracts/openapi/group-my-submissions.yaml. Real database tests cover own-only including OWNER, foreign Group/Space, pending/empty Group, mixed Studies/states, current labels/original instruction versions, filtered paging, exact grade/marker/zero/rubric meanings, no writes and concurrent snapshot. API/Gateway tests cover every role, strict session/path/query/body and authority loss. Browser checks original answer/score/reason, actual confirmed resubmission, independent drafts, fresh role, exact selection, privacy recovery, both entry points and mobile. Evidence: group-my-submissions-validation.txt and .local/group-my-submissions-validation.json. Resource-limited functional runs use existing --serial without changing assertions/timeouts.
