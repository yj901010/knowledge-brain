# Course assignment overview with own submission presence

On /graph/groups, open Group -> Course -> 코스 내 미제출 과제 확인. Fresh current OWNER/MEMBER/VIEWER reads shared assignments from Studies currently in the canonical Course curriculum, with only own submission presence. This uses existing shared Course/Study read rights and works independently of enrollment. OWNER also sees only own presence here. No peer submission, roster, private progress, answer, grade or reason is copied. Empty curriculum yields an empty list; removed Studies disappear on refresh. One Study may remain referenced by other Courses without duplicating assignments inside one Course.

OPEN_NOT_SUBMITTED default requires OPEN Assignment, non-RETIRED Study and Course, and absent own submission. OPEN keeps the same parent guards with either presence. ALL/SUBMITTED/NOT_SUBMITTED retain shared DRAFT/CLOSED/RETIRED reads, including archives. Course COMPLETED is distinct from archive. These predicates are point-in-time discovery, never submission permission, personal assignment obligation, deadline or learning completion. Retiring a Course does not archive its independent Studies; original Study/Assignment write rules remain authoritative. VIEWER can inspect own presence without submission rights.

Eleven fields extend the same own-presence metadata with current Study ID/title and Course state. Current source labels never rewrite the Course's pinned selected Study title/version or its immutable history. Submitted instruction versions stay separate from current Assignment versions. List order is ascending Assignment UUID keyset across Studies, default20/max100 and limit+1, independently of curriculum position. Source/curriculum changes may shift pages; explicit refresh restarts from the beginning.

GET /api/groups/{groupId}/courses/{courseId}/my-assignments accepts singleton filter/after/limit, canonical UUIDv7, empty GET body, registered secure singleton session and no-store. Space reauthorizes current Group participation before Course/local reads. One statement joins only Collaboration-owned Course, course_study, current Study, Assignment and actor-bound optional Submission with full Group/Space/Course/Study/Assignment tuples. Existing course_study unique keys, Study/Assignment catalogs and Assignment/author unique index support bounded local reads. No cross-owner SQL/FK, canonical write, enrollment, persistent ID/revision/Outbox, migration, event schema, dependency/dataset, notification or progress/sharing mutation. Fixed assignment.reads type=course-mine and existing traces/pool/probes apply; no content in logs/metrics.

Collapsed memory-only UI validates exactly eleven fields, null triples/version bounds, filter agreement, current Course-state consistency and ordered cursor. Filter/refresh preserves open answer and Course edit drafts. Failed/malformed reads clear rows/cursor with explicit retry. Row selection first rereads Course and confirms the Study still belongs to current curriculum, then opens original freshly authorized Study and Assignment through optional initial source IDs. Same-Study different Assignment selections get a fresh source mount. A removed binding stops navigation and asks for explicit list refresh; it never opens stale Course membership. Hidden/unmounted/denied state aborts and clears, including nested source details. No polling or persistent browser storage.
