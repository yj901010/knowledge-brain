# Group-wide own assignments

On /graph/groups, every current registered Group participant opens Group -> 그룹 내 미제출 과제 확인. The collapsed memory-only overview spans shared Assignments in all canonical Studies in the exact Group/Space, including standalone Studies without Course relationships. It includes only the freshly authenticated actor own submission presence, even for OWNER. MEMBER and VIEWER share the existing definition-read policy; VIEWER remains unable to submit. No peer presence/roster, score, answer, reason, individual obligation or private completion is inferred. Current Space participation and matching ACTIVE Collaboration Group configuration precede SQL on every request; removed participation loses access.

OPEN_NOT_SUBMITTED default requires OPEN Assignment, nonarchived Study and no own submission. OPEN ignores own presence but still excludes archived Studies. SUBMITTED and NOT_SUBMITTED are own-presence predicates, while ALL retains existing DRAFT/CLOSED/RETIRED shared reads. These are point-in-time metadata filters, never write permission or assignment obligation. Completed Study operational state is independent of private Learning completion. Archived definitions retain reads with original source restrictions.

Ten fields: current Assignment ID/title/state/version, current Study ID/title/state, own Submission ID/version/submitted Assignment version or three nulls. Current labels never rewrite submitted instructions. No author ID/peer count, answer, score, reason, rubric or file copies. Explicit row selection rechecks current Group participation and remounts the exact original Study/Assignment flow using the fresh OWNER flag. Same-Study different-Assignment and cross-Study selection opens fresh source; current source APIs govern actual submit permission, confirmation/CAS/idempotency and pinned original instructions. Queue refresh/filter preserve open answer and Study edit drafts. Source close, Group switch, hidden tab/unmount and authority loss clear the target. Both owned and participating entry points use the same workspace.

GET /api/groups/{groupId}/my-assignments accepts singleton filter/after/limit, canonical UUIDv7, empty GET body, default20/max100, registered secure singleton session and no-store. Active local Group/Space check precedes one canonical Assignment/Study metadata statement left-joining only the authenticated author Submission with the full Group/Space/Study/Assignment tuple. Metadata/presence share one snapshot. Existing Group/Study/Assignment catalog and Assignment-author keys are reused. Predicates precede limit+1 and ascending Assignment UUID keyset; pages are current reads, refresh begins at the start. No Course/curriculum/enrollment query or cross-owner SQL/FK.

UI validates exact ten fields, enums, nullable own-presence tuple, submitted/current version relationship, requested filter and bounded ordered cursor. Study states may differ across rows. Invalid/error responses clear rows/cursor with explicit retry and no false empty result. Hidden/unmounted views abort/clear; authority loss clears parent Group. No polling or persistent browser storage. A freshly changed participant role is used for source controls, including VIEWER readonly and MEMBER submission under original rules.

No new persistent ID/revision/Outbox, migration, published Proto, dependency/dataset, Course creation, enrollment, notifications, unread tracking or private progress/sharing mutation. Fixed assignment.reads type=group-mine and existing traces/pool/probes apply without private content logging. Existing Group/Study/Course queues, own overviews and source writers remain unchanged. This packages existing shared-definition and own-submission rights without architecture restructuring.

OpenAPI: contracts/openapi/group-my-assignments.yaml. API/Gateway tests cover every role with current actor, revocation and strict path/session/query/body. Browser proof covers real submission, fresh exact source reselection, current role/VIEWER, Group switching, drafts, recovery/privacy/mobile, both entry points and existing regressions.
