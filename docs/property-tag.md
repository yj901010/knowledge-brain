# 태그와 속성 조건 함께 적용하기

`/graph`의 **내 노트 목록 → 속성 탐색 열기 → 속성 선택 → 태그 조건 고르기**에서
태그를 고르고 **태그 조건 적용**을 누른다. 선택한 속성을 사용하는 노트 중 그 태그도
있는 노트만 조회한다. 기존 정확한 값 또는 숫자·날짜 범위를 적용하면 모두 만족하는
노트를 찾는다. 예: `공부` 태그와 `점수 80 이상`.

태그 목록은 20개씩 더 불러온다. 사용하지 않는 태그도 표시하며 해당 조건의 결과는
빈 목록이다. 태그 선택만 바꿔서는 결과가 바뀌지 않는다. **태그 조건 적용**은 현재
적용된 값 조건을 유지하고, **값 조건 적용**은 현재 적용된 태그를 유지한다. 입력 중인
다른 조건은 함께 적용하지 않는다. 다음 페이지와 노트 새로고침도 적용 조건을 유지한다.

[태그 이름 검색](metadata-name-search.md)으로 목록을 좁혀 선택할 수 있다. 이름 검색은
태그 선택 초안만 초기화하며 현재 적용된 태그·값 조건과 노트 결과는 유지한다.

**태그 조건 해제**는 값 조건을, **값 조건 해제**는 태그 조건을 유지한다. 태그 목록
닫기는 적용한 태그를 유지하며 선택 초안만 지운다. 속성 선택 변경·해제와 전체 탐색
닫기는 두 조건을 모두 초기화한다. 탐색은 노트 편집 초안을 바꾸지 않는다.

현재는 속성 하나와 태그 하나를 AND로 조합한다. 여러 태그·속성이나 OR 조건은
별도 확장이다. 속성·태그 목록의 개수는 조합 조건 적용 전 전체 활성 노트 개수이다.
페이지는 실시간 조회이며 snapshot이나 일치 개수 집계는 아니다.

태그 목록 조회 실패는 선택 초안을 비우고 새로고침을 안내하며 적용 결과를 유지한다.
노트 조회 실패나 다른 적용 태그가 표시된 응답은 결과를 비운다. 닫힌 선택기·변경 전
조건의 늦은 응답은 버린다. 접근 철회는 개인 화면을 초기화한다. 목록·조건을 브라우저
저장소에 쓰지 않으며 탐색 중 도메인 데이터를 변경하지 않는다.

## API와 기존 결정

`GET /api/spaces/{spaceId}/property-definitions/{propertyId}/notes`에 선택적
`tagId` query를 추가한다. 같은 Space에 정의된 태그의 canonical 소문자 UUIDv7이다.
생략하면 태그 조건이 없으며, 선택한 속성의 존재 조건은 항상 적용된다.

```text
?tagId=<UUIDv7>
?tagId=<UUIDv7>&value=false
?tagId=<UUIDv7>&minValue=80&maxValue=100&limit=20
```

`value`와 `minValue`/`maxValue`는 기존처럼 서로 배타적이다. `tagId`는 어느 쪽과도
함께 쓸 수 있다. 다음 페이지에도 같은 조건을 보내야 한다. 알려진 미사용 태그는
빈 페이지, 없는 태그·다른 Space의 태그는 404이다. 잘못된·빈·중복 tagId는 400이다.
다른 태그/속성 목록이나 태그별 노트 경로는 이 query를 허용하지 않는다.

응답에 `tagId`를 추가해 적용한 ID를 반환하고 조건이 없으면 null을 반환한다.
기존 `{propertyId,name,type,items,nextAfter}`와 노트 item 형식은 유지한다.
`after` UUIDv7, `limit` 기본 20·최대 100, UTF-8 query 총 길이 2600자 제한,
현재 Space 권한 확인, PRIVATE/ACTIVE 노트와 `Cache-Control: no-store` 규칙도 유지한다.
조회 본문과 쓰기 메서드는 Gateway에서 거절한다.

AGENTS.md와 PROJECT.md의 결정과 충돌하지 않는다. Content가 소유한 PostgreSQL의
`content_tag`, `note_tag`, `property_definition`, `note_property`, `note`만 조회한다.
태그 정의를 같은 Space에서 확인하고 `EXISTS`와 바인딩한 ID를 사용해 값 조건과
함께 커서·LIMIT 전에 적용한다. V3 `note_tag_lookup`과 V13 `note_property_lookup`
인덱스, 기존 `brain.content.metadata.reads{type=property_notes_filtered}`를 사용한다.
새 migration·의존성·이벤트 계약이나 정본 변환은 없다.

## 검증

실제 PostgreSQL/Kafka와 Gateway에서 조건 교집합, 정확한 소수, 20+2 페이지,
다섯 타입·날짜 범위, 미사용·미등록·타 Space 태그, 연결 해제·폐기 제외와 읽기
부작용 없음을 검증한다. 로컬 Kubernetes 브라우저에서는 25개 태그의 페이지 선택,
독립적인 선택·값·편집 초안, 각 조건 해제, 모바일 폭, 실패 복구·잘못된 응답·지연과
접근 철회를 확인한다. 기존 속성·태그·메타데이터·노트 목록·폐기 회귀를 함께 수행한다.
실행 결과는 [검증 기록](property-tag-validation.txt)에 기록한다.
