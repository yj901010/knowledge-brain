# Public knowledge, discovery and recovery bundle

## Scope and architecture

The user requested the remaining public knowledge and search/graph work as one large package with recommended defaults. Existing thirteen service boundaries, owner databases, local ACID, REST/JSON, UUIDv7, immutable published event contracts, Outbox→Debezium/Connect→Kafka and private defaults are preserved. No new runtime dependency, PVC, service, clinical dataset, AI or automatic public promotion is introduced. Knowledge owns the canonical public facts and reviews; Brain Query owns disposable public read models.

## Qualified claims and verification

QUALIFIER joins the existing CREATE/UPDATE/RETIRE proposal, independent reviewer approval, CAS merge and immutable revision/history flow. Exact content is claimId/claimVersion, predicateId/predicateVersion, valueType/value/valueVersion. Types are CONCEPT, STRING, NUMBER, DATE, BOOLEAN; literal valueVersion is zero and canonical decimal values remain exact strings. All references must be current same-public-Space versions at submission and merge. A qualifier stays attached to its original Claim revision; another Claim revision requires a new qualifier identity. At most100 qualifier identities per Claim revision, including retired identities, keep verification scope bounded.

VERIFICATION accepts a separate additive top-level qualifierPins object. It contains the inspected current version of every qualifier identity for that exact Claim revision, including retired identities. Retirements remain in scope so adding then retiring a qualifier cannot revive an old assessment. The legacy six-field verification content and existing public-record v1 payload remain unchanged. Existing records default to empty pins. Missing pins mean empty; a nonempty scope must be inspected explicitly. Reference/scoping changes between submission and merge fail412. Scope changes require a new DRAFT/SOURCED assessment revision before progressing again. The effective read becomes DRAFT/needsReview when qualifier versions, Claim/Concept context or evidence/source grounds no longer agree. The browser shows scope before submission and history retains captured pins. Designated independent reviewers and separate expert/official capabilities keep their existing meanings.

## Public projection

A new standalone Protobuf artifact `knowledge/public-knowledge-events` v1 and topic `knowledge.public-knowledge.v1` carry normalized PUBLIC Concept and all seven fact kinds. Qualifier proposal transitions use a separate envelope event type on this new stream; consumers validate and ignore them. Old contracts/topics/content are byte-preserved. Writers insert the new canonical event inside the same owner transaction; only Connect publishes Kafka records.

Brain Query V5 owns a durable event inbox, current source snapshots, global external sequence, pending work and feature availability control. Duplicate event IDs require identical bytes; same-version canonical conflicts, moved entity IDs and resurrection after retirement fail closed. Canonical snapshot hashes normalize JSON object ordering and integer width so PostgreSQL jsonb recovery and event replay agree. Parent/dependent work is queued when names, aliases, qualifiers or reference sources change. Kafka offsets advance after durable staging. Both graph/search writes must succeed before removing pending work. External sequence/hash checks make partial failure and restart retryable.

The fixed OpenSearch index is `brain-public-knowledge-v1`; existing scoped reader/projector mTLS roles gain only this fixed index. JanusGraph stores separate `pubEntity`/`pubRelation` vertices, role-labelled edges and pub* properties/indices in the existing Cassandra-backed graph. Private brain*/Note projections remain separate. Literal values never become Concept edges. Public Kafka identity can only read the new topic and the fixed `brain-query-public-v1` group. Telemetry contains event/trace IDs and bounded kind/outcome counters, not titles, content, keys or credentials.

## Reads and limits

Gateway exposes GET `/api/public/spaces/{spaceId}/search` and `/graph` only. Every request resolves the current application principal through Space/Identity and requires an active PUBLIC catalog Space. Pending proposals, private and foreign rows are excluded. Query then checks each projected candidate against current public canonical metadata through a separate bounded HTTPS service credential. Live hydration uses batches of eight so even existing maximum32KB Concept text with worst-case JSON escaping remains within the2MiB response bound. Normalized event decoding accepts up to256KiB, including up to200KB escaped content, without reducing the established canonical text limit. Changed canonical versions and invalid dependent context are omitted. Claim badges use current effective verification; stale expert/official context is never inferred from index text. Public data returned is a point-in-time read; refresh to observe later changes.

Search: q1..128 code points, optional eight-kind filter, limit1..50, offset+limit<=1000. It searches title, own text and same-Space referenced names/aliases/qualifiers. `projectedTotal` is an eventual index total, not a count of freshly validated results. `staleOmitted` explains omissions and paging follows the bounded projected window. Graph: optional UUIDv7 center, depth1..3, limit1..100, maximum300 displayed edges and1000 incident-edge visits per frontier vertex. Uncentered views are bounded samples. SVG selection, pan, zoom, depth, center navigation and an accessible text list are available. Search/graph/authority failure returns503 without canonical table-scan fallback.

Knowledge's `/internal/knowledge/public-check` checks1..50 distinct IDs in one Space and returns public canonical metadata/current context only. Its live read credential cannot use `/internal/knowledge/public-snapshots`. The scan credential is operator-only, absent from live Query, and the scan excludes private Concepts/proposals. HTTPS, exact service authentication, no browser Cookie and bounded requests are enforced; neither internal route is exposed by Gateway.

Five medicine topic names and seven development/CS topic names are included. Exact entity revisions/source links, CC0-1.0 evidence and the legal text are retained. ## Local operation and recovery

One-time provisioning: `Prepare-PublicDiscovery.py --helm <absolute-helm-path>` registers/verifies the new immutable contract and prepares topic/producer ACL/read-only user; `Provision-PublicDiscovery.py` preserves existing secrets and copies scoped user/scan credentials only to their required namespaces. Apply OpenSearch chart role changes, then `Initialize-PublicSearch.py` to initialize the fixed public index/security roles. Service/local values distinguish enablement; normal Query never receives graph/search administrator or scan credentials.

`Install-LocalPublicDiscovery.py --helm <absolute-helm-path>` builds/imports/rolls Space, Knowledge, Brain Query, Gateway sequentially, preserves telemetry and Deployment UIDs, records immutable source/image evidence, then removes only its owned ephemeral builders. `--refresh-services knowledge brain-query` explicitly refreshes changed sources without repeating completed services.

`Rebuild-LocalPublicDiscovery.py` runs a bounded, tokenless operator Job in brain-data. It preflights both Knowledge public feeds, takes an operator lock, durably marks only public discovery unavailable and waits for the public Kafka group to release. Private Query stays deployed. It captures topic end offsets BEFORE resetting only the fixed public search index, pub* graph namespace and Query-owned public inbox/source/work. It scans fenced canonical public Concept/record feeds including retired rows, drains work, replays the captured Kafka tail, drains again and commits checkpoints before making the feature available. Subsequent CDC arrivals are consumed normally. No synthetic domain publication, owner mutation, private reset or cluster/PVC deletion occurs.

Any failed rebuild remains unavailable. Inspect its retained Job/evidence and retry the same public-only command after fixing the cause. Do not mark available by hand, reset unrelated offsets or delete canonical data. Retention gaps and conflicting snapshots require this canonical rebuild. `--pause` is a bounded validation handshake after snapshot projection; an operator/test may touch only that Job's `/tmp/rebuild.resume` to continue. Concurrent writes after the fence are covered by replay and subsequent durable consumption.

Cold backups already inventory all13 PVCs and matched configuration/images/credentials. New public tables/namespaces use those existing volumes; no backup architecture change is required. The actual validation for this bundle is recorded separately in `public-discovery-validation.txt` and `.local/public-discovery-*.json`. Prior backup/restore and prior public-workbench proofs remain historical, unchanged.
