# Course own resubmission requests

On /graph/groups, open Group -> Course -> 코스 내 재제출 요청 열기. Current registered OWNER/MEMBER/VIEWER sees only existing requests attached to own submitted work in Studies currently in canonical Course curriculum, independently of enrollment/private progress. OWNER also sees only own requests. No-request submissions, peers, non-submitters and roster counts are absent. Empty curriculum produces an empty list. Removed links disappear after refresh; explicit source selection freshly rechecks current curriculum then original Study/Assignment authority.

REQUESTED is the default; ALL (existing requests), RESOLVED, CANCELLED and UNAVAILABLE are alternatives. REQUESTED targets the current answer without resolution; CANCELLED retains its original target with no resolution; RESOLVED requires requested < resolved <= current answer. Later answers preserve first resolution; correcting/cancelling/re-requesting uses existing independent request versions. Old submission replay cannot resolve a later request. Unknown/missing or inconsistent state is UNAVAILABLE. Resolution means newer answer arrival, never grading or learning completion. Closed/archived sources retain shared/own reads; the list never reopens submissions. Original source controls current write eligibility.

Fourteen fields extend the eleven-field Study own-request row with current Study ID/title and Course state. Assignment labels are current; original submitted instruction/request-target/resolving versions remain pinned. Current labels do not rewrite Course selected Study snapshots/history. No reason, answer, score, reviewer identity, rubric or file data is copied. The original submission supplies private reason and immutable history. Independent list refresh/filter preserve answer and Course edit drafts; explicit selection opens the source, including same-Study different assignments.

GET /api/groups/{groupId}/courses/{courseId}/my-resubmission-requests accepts singleton filter/after/limit only, canonical UUIDv7, no GET body, default20/max100, registered secure singleton session and no-store. Space freshly authorizes each request; current VIEWER retains own read and removed participants lose Group access. One statement joins only local Course/current curriculum/Study/Assignment/actor Submission/Request canonical metadata with full tenancy and author tuples; state and source versions share one snapshot. Existing curriculum/catalog/Assignment-author/Request-submission keys support bounded reads. Filters precede limit+1 ordered by Submission UUID. Pages reflect current reads; refresh starts from the beginning.

Collapsed memory-only UI validates exact fields, states, version/null relationships, requested filter, common Course state and ordered bounded cursor. Failed or malformed replies clear rows/cursor, show an explicit retry and no false empty result. Hide/unmount abort and clear state; denied access clears Group detail. No polling or persistent browser storage. Stale curriculum binding blocks source navigation pending refresh. No cross-owner SQL/FK, new IDs/revisions/Outbox, migration, published Proto, dependency/dataset, enrollment, notification, private progress/sharing change. Existing source request writers and Study/Course overviews remain unchanged. Submission read metric type=course-mine-requests, pool/probes/traces remain fixed-label without private content.
