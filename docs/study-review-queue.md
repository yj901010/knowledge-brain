# OWNER Study feedback and request review queue

On /graph/groups, current OWNER opens Group -> Study -> 스터디 피드백·재제출 검토목록 열기. The collapsed memory-only queue spans submitted work in all Assignments in one Study, including standalone Studies without any Course relationship. Existing OWNER own-submission feedback/request workflows are included; the separate grading queue and writer still forbid self-grading. No non-submitter roster, profile lookup, enrollment or private progress requirement. Current registered Space OWNER authority precedes local SQL on every request. MEMBER/VIEWER403 even for empty queues; removed participation loses Group access.

NEEDS_FEEDBACK is default: missing, older-answer, exact latest withdrawn or unavailable feedback. HAS_FEEDBACK requires known current-answer latest feedback and absent/restored annotation. RETRACTED_FEEDBACK includes exact latest-version withdrawal on current or older answer, excluding unavailable feedback. Historical markers never mark newer comments. Independent PENDING_RESUBMISSION requires a request for the current answer without resolution. CANCELLED preserves its source without resolution; RESOLVED requires requested < resolved <= current answer. Later answers retain first resolution; old replay cannot resolve a later request. Unknown/missing/inconsistent metadata becomes UNAVAILABLE, never current feedback or pending/resolved request. UNAVAILABLE includes either unsafe dimension; known current feedback may coexist with an unavailable request. ALL includes all submitted rows. Request resolution means new answer arrival, never grading, approval or learning completion.

Eighteen metadata fields: Submission/author/source versions/time; normalized feedback status/version/source, exact latest-version retraction state/version and needsFeedback; request version/state/source; current Assignment ID/title/state and Study state. Original submitted instruction versions remain pinned. No answer, comment, request/retraction reason, score, reviewer identity, rubric or file contents. Selecting a row refreshes current Study context and opens exact original Assignment/Submission under existing authority/confirmation/CAS rules. Same-Assignment author and cross-Assignment reselection remount source. Independent queue refresh/filter preserve feedback/request and Study edit drafts. Explicit Study changes clear prior target; existing Course source pointers and grading queue source behavior remain unchanged. Archives retain reads with original source write restrictions.

GET /api/groups/{groupId}/studies/{studyId}/submissions/review-queue accepts singleton filter/after/limit, canonical UUIDv7, empty GET body, default20/max100, registered secure singleton session and no-store. One statement joins local Study/Assignment/Submission/Feedback/exact feedback-version Retraction/Request with full Group/Space/Study/Assignment/author tuples. Source and atomic request resolution share one snapshot. Existing Study/Assignment catalog, Assignment-author, feedback-submission and marker/request keys support bounded reads; predicates precede limit+1 and ascending Submission UUID keyset. Pages are current reads; refresh begins from the start. No Course/curriculum/enrollment query.

UI validates exact eighteen fields/enums, nullable versions, feedback classification/needs relationship, normalized request source bounds, requested filter, common Study state and bounded ordered cursor. Invalid/error reads clear rows/cursor with explicit retry and no false empty result. Hide/unmount aborts/clears; authority loss clears Group detail. No polling or persistent storage. Existing per-Assignment review contract retains twelve fields, five filters and ALL default. UNAVAILABLE remains restricted to the separate Course/Study overview routes.

No cross-owner SQL/FK, persistent ID/revision/Outbox, migration, published Proto, dependency/dataset, Course creation, enrollment, notification, unread tracking or private progress/sharing mutation. Fixed submission.reads type=study-review-queue and existing traces/pool/probes apply without private text logging. This reuses established submitted-work read and source-write policies without architecture restructuring.
