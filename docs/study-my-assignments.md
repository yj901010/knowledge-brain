# Study assignments with own submission presence

On /graph/groups, open Group -> Study -> 스터디 과제 -> 내 미제출 과제 확인. Current registered OWNER/MEMBER/VIEWER sees existing shared assignments with only their own submission presence. Another participant's submission never fills that presence. OWNER sees only own submission presence here; existing OWNER review/grading and own submission/request/feedback overviews retain their original endpoints and exact shapes. This does not produce a member roster or identify other non-submitters.

OPEN_NOT_SUBMITTED is default: OPEN Assignment, non-RETIRED Study, and no own submission. OPEN shows OPEN assignments in a nonarchived Study regardless of own submission. ALL shows every shared definition permitted by the existing Assignment read policy, including DRAFT/CLOSED/RETIRED. SUBMITTED/NOT_SUBMITTED apply only own presence across those states. Archived Study removes rows from both OPEN filters, while ALL/presence filters retain reads. A COMPLETED Study remains writable under existing policy. Filters do not infer individual assignment obligation, actual permission, deadlines or private learning completion. Current VIEWER may inspect absent/present own work but cannot submit; original detail freshly authorizes writes.

Eight metadata fields: assignmentId/title/state/current version/studyState and nullable submissionId/submissionVersion/submittedAssignmentVersion. The three own-submission values are all null or all present and positive, with submittedAssignmentVersion <= current definition version. No answer, comment, score, reason, author selector or peer data is copied. Row selection explicitly opens the original freshly authorized Assignment; its existing component loads latest instructions and own current answer/eligibility. Submitted instruction versions remain pinned independently of subsequent shared definition edits.

GET /api/groups/{groupId}/studies/{studyId}/my-assignments accepts singleton filter/after/limit only, canonical UUIDv7, default20/max100, empty GET body, secure registered singleton cookie, no-store. Fresh Space Group participation precedes local reads. One statement joins own Collaboration Assignment and Study metadata to only the authenticated actor's Submission using exact Group/Space/Study/Assignment scope. The actor predicate stays inside LEFT JOIN so absent own work survives without ever joining peers. Filters precede limit+1, ascending Assignment UUID keyset. Existing Study/Assignment catalog and Assignment/author unique index support this read. Pages reflect current state; refresh begins at the start. No cross-owner SQL/FK, mutation, persistent ID/revision/Outbox, migration, event contract, dependency/dataset, notification, sharing or progress change. Fixed-label assignment.reads type=study-mine, existing pool/probes and traces apply; no private text in logs/metrics.

Collapsed memory-only UI validates exact fields, state enums, null triples, safe version bounds, filter agreement, consistent Study state and ordered cursor. Invalid/failed responses clear rows/cursor and offer explicit retry without a false empty result. Filter/refresh preserve typed answers; explicit selection opens current source. Hide/unmount aborts and clears; denied access clears participant Group detail. No polling or persistent browser storage.
