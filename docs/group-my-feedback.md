# Group-wide own feedback

On /graph/groups, current registered participants open Group -> 그룹 내 피드백 열기. The collapsed memory-only overview lists only existing feedback on the fresh actor submitted work across all canonical Studies in the exact Group/Space, including standalone Studies without Course bindings. Independent of enrollment/private progress. OWNER receives only own feedback here, including existing permitted OWNER own-review. VIEWER retains own reads and original write restrictions. Current Space participation and matching ACTIVE Collaboration Group configuration precede SQL on every request; removed participants lose access.

ALL default; CURRENT, OUTDATED, RETRACTED, UNAVAILABLE retain Study/Course semantics. Current versus older-answer feedback and latest-version annotation are separate dimensions. Resubmission leaves earlier-answer feedback OUTDATED. RETRACTED includes an older-answer latest feedback with a withdrawn marker. Only the exact latest feedback-version marker applies; an historical withdrawal cannot mark a newer feedback version. Missing/unknown marker state or impossible newer-answer feedback becomes UNAVAILABLE, never CURRENT. Feedback metadata never means grading, passing, unread state or private completion. Overview reads do not write feedback, annotations or notifications.

Fifteen fields: Submission ID/version/submitted Assignment version/update time, feedback status/latest feedback version/feedback submission version/exact marker state/version, current Assignment ID/title/state and current Study ID/title/state. No author ID, peer roster/count, unannotated or unsubmitted rows, opinion, reason, answer, score, rubric or file copies. Current labels preserve submitted instruction versions. Archived definitions retain existing reads; mixed Study lifecycle states are valid and Study completion remains separate from private Learning completion.

GET /api/groups/{groupId}/my-feedback accepts singleton filter/after/limit, canonical UUIDv7, empty GET body, secure singleton registered session and no-store. Ascending Submission UUID keyset/default20/max100, predicates before limit+1. One Collaboration-owned statement joins Submission/Assignment/Study and existing Feedback with full Group/Space/Study/Assignment/author scope, then the exact latest feedback-version marker. Concurrent answers/opinions share a statement snapshot. Existing indexes are reused; no Course query, cross-owner SQL/FK, new persistent IDs/revisions/Outbox, migration, published Proto or dependencies/datasets.

Explicit selection rechecks participation, then remounts exact original Study/Assignment using the fresh OWNER flag. Original APIs supply private comments/reasons/answers, current version state and CAS/confirmation/idempotency/permission rules. Same-Study different-Assignment, cross-Study and repeat selection load fresh original sources. Overview refresh/filter preserve open answer and Study edit drafts. Source close, Group switch, hidden tab/unmount and authority loss clear target. Both owned and participating Group entry points share the workspace. Newly changed VIEWER role receives readonly controls and original submit API403.

UI validates exact15 fields, safe versions, IDs, bounded labels, lifecycle/feedback/marker enums, nullable marker tuple, derived status, requested filter and ordered bounded cursor. UNAVAILABLE is explicit. Invalid/error responses clear rows/cursor with retry and no false empty result. Hidden/unmounted views abort/clear; authority loss clears Group. No polling/browser persistent storage, unread tracking, Course creation, enrollment, notification or private progress/sharing mutation. submission.reads type=group-mine-feedback and existing traces/pool/probes apply without private content logging. Published queues, own views, GatewayController and source writers remain unchanged; Group parents add only workspace import/panel.
