# 이전 노트 내용을 새 버전으로 저장

활성 개인 노트에서 **수정 이력 → 이전 버전 선택 → 이 내용으로 복원 준비**를
누르면 해당 제목과 Markdown을 편집 초안으로 가져온다. 현재 저장된 내용도
펼쳐 확인할 수 있다. 필요하면 초안을 편집한 뒤 **이전 내용으로 새 버전 저장**을
누른다. 준비·취소·조회는 쓰기를 발생시키지 않는다.

## 범위와 기존 결정

AGENTS.md와 PROJECT.md의 데이터 소유권, 불변 이력, 개인 공간 기본 비공개,
서비스 경계와 Outbox 결정을 유지한다. Content의 기존 GET/history와
If-Match PUT을 사용한다. 기존 Note ID에 새로운 버전과 NoteUpdated 이벤트가
생기며, 이전 수정 이력은 수정하지 않는다. 선택한 과거 버전은 초안의 출처로
화면에 표시한다. 별도의 서버 복원 명령이나 복원 출처 필드를 추가하지 않았으며,
새 이력의 actor는 현재 저장한 사용자다.

이번 기능은 활성 노트의 제목·본문을 대상으로 한다. 태그·속성, 첨부파일,
Note↔Concept 연결과 Daily Note 날짜·시간대는 독립적으로 보존한다. Wiki Link는
저장한 본문으로 다시 계산하고, 검색·그래프·활동 이력은 기존 이벤트 처리로
반영한다. 폐기된 노트를 활성화하는 기능은 포함하지 않는다.

API·이벤트·DB 스키마, 서비스 경계, 외부 데이터와 의존성 변경은 없다.
기존 Content 변경 카운터와 HTTP/이벤트 추적을 사용한다.

## 동시 수정과 실패 처리

복원을 준비할 때 최신 활성 노트를 다시 읽고 그 응답의 강한 ETag를 사용한다.
선택한 이력은 현재 버전보다 이전이어야 한다. 이력의 Note ID, UUIDv7,
본문 제한, 버전 순서와 중복 여부를 검증한다. 현재 노트의 Space/PRIVATE/ACTIVE와
응답 버전·ETag 일치도 확인한다. 이력은 기존 5개 페이지 조회를 유지한다.

저장 시 412가 오면 복원 초안은 유지하고 추가 저장을 막는다. **최신 내용 확인** 후
**최신 버전 기준으로 복원 다시 확인**을 선택하면 초안을 유지한 채 기준만 갱신한다.
사용자는 다시 내용을 확인하고 저장해야 한다. 기존 **최신 버전으로 다시 시작**은
초안을 현재 내용으로 바꾸며 복원 모드를 종료한다. 자동 재시도·병합은 없다.

일시적 저장 실패 시 초안을 유지한다. 서버에서 저장했지만 응답이 유실된 경우에도
재시도는 원래 ETag를 보내므로 이미 저장된 버전을 몰래 덮어쓰거나 중복 저장하지
않는다. 이력 조회 실패는 이력 화면을 비우고 명시적으로 재시도한다. 복원 준비
실패는 선택한 이력을 유지하며 저장 화면으로 이동하지 않는다.

## 개인 데이터 수명

초안은 메모리에만 유지한다. Note/Space 변경, 로그아웃과 기존 비공개 화면 숨김
정책에 따라 사라진다. 늦게 도착한 응답은 이전 컴포넌트를 되살리지 못한다.
401/403/404는 초안·현재 내용·수정 이력을 지우고 상위 개인 화면을 다시 검증한다.
클라이언트 검사와 별도로 모든 조회·저장은 서버의 최신 권한 검증을 거친다.
복원 텍스트는 기존 안전한 Markdown 미리보기와 텍스트 입력을 사용한다.

## 검증과 배포

`Run-GraphWebValidation.py --note-restore-regressions`는 실제 로컬 HTTPS/Content/
PostgreSQL/MinIO와 읽기 모델을 사용한다. 복원 시나리오 6개와 기존 편집, Markdown,
폐기, 메타데이터, Journal, Wiki Link, 첨부, Concept 연결 회귀 검증을 실행한다.
Gateway 정적 프론트만 새로 빌드·배포하며, 다른 서비스의 이미지는 유지한다.
