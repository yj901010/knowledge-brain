# Course own submissions and grading metadata

On /graph/groups, open Group -> Course -> 코스 내 제출·채점 현황 열기. Fresh current registered OWNER/MEMBER/VIEWER reads only own submitted work from Studies currently in canonical Course curriculum. OWNER sees only own work here. Empty curriculum or absence of own submissions produces an empty list without creating records. Removed curriculum links disappear on refresh; source selection rechecks current Course binding. This uses existing shared Course/Study and own Submission read rights independently of enrollment/private progress. No peer roster or unsubmitted work is inferred.

ALL default; MISSING means no grade, CURRENT means grade targets the latest submitted answer with absent/restored annotation on that exact latest grade version, OUTDATED means its source is an older answer, RETRACTED means current-answer latest grade is withdrawn, UNAVAILABLE means unsafe source/marker metadata. NEEDS_GRADING includes every status except CURRENT, as in the Study overview. Direct and rubric score0 count as grade records. Neither metadata presence nor filter implies passing, approval, private completion or write permission. Old-answer withdrawal remains OUTDATED; older grade-version markers cannot mark newer grades. Existing shared archived Course/Study/Assignment and own submission read policy remains; original source controls still govern writes.

Fifteen fields extend the twelve-field Study row with Study ID/current title and Course state. Source Assignment labels are current, while submitted instruction and grade-source answer versions stay pinned. Course-selected Study titles/version history are never rewritten. Scores, reasons, answers, rubric details, files and reviewer identity remain only in original authorized submission. Selecting a row reuses current-Course verification and fresh Study/Assignment source opening. No stale overview metadata is used for a command; same-Study source selections remount current source. Filter/refresh preserve typed answer and Course edit drafts.

GET /api/groups/{groupId}/courses/{courseId}/my-submissions accepts singleton filter/after/limit, canonical UUIDv7, empty GET body, registered secure singleton cookie and no-store. Space freshly reauthorizes Group participation before Course/local reads. One statement joins only local Course/current curriculum/Study/Assignment/actor Submission/Grade and exact latest grade-version Retraction metadata with full tenancy scope. Source and marker versions share its snapshot. Existing course_study, Study/Assignment catalog, Assignment/author and grade/submission/marker unique keys support bounded reads. Filters precede limit+1, ordered by Submission UUID, default20/max100. Current pages may shift; explicit refresh starts at the beginning. No cross-owner SQL/FK, enrollment, persistent ID/revision/Outbox, migration, published Proto, dependency/dataset, notification or progress/sharing mutation. Existing submission.reads type=course-mine, traces/pool/probes apply; content is absent from metrics/logs.

Collapsed memory-only UI validates exact fields, enums, version/null/marker relationships, requested filter, common Course state and ordered cursor. Failed/malformed/wrong-filter replies clear rows/cursor with explicit retry and no false empty result. Hide/unmount/denial aborts and clears; revoked access clears participant Group detail. No polling or persistent browser storage. Source binding changes block stale navigation until list refresh. Original source text, grade version and private history remain visible under existing source rules.
