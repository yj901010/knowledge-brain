# OWNER Course grading queue

On /graph/groups, current OWNER opens Group -> Course -> 코스 채점 대기 목록 열기. The collapsed queue spans Studies in current canonical Course curriculum and shows only other authors submitted work. OWNER self submissions stay excluded under no-self-grading. No non-submitter roster or enrollment/private progress is inferred. MEMBER/VIEWER cannot read even an empty queue; removed participation loses Group access. Every request freshly checks registered Space OWNER authority before Collaboration reads. Existing own overviews and per-Assignment review/grading APIs remain unchanged.

NEEDS_GRADING default includes all except CURRENT. ALL, MISSING, CURRENT, OUTDATED, RETRACTED and UNAVAILABLE retain original grading queue meanings. Zero/direct/rubric count as grade records. Latest grade applies only to its exact source answer; annotations join exact latest grade version. Old-answer withdrawn grade stays OUTDATED; historical markers on an older grade never mark a newer one. Unknown marker or future source is UNAVAILABLE, never current. Metadata does not mean passing, verification, completion or write permission. Original source controls still govern commands, including archived read-only Study/Assignment rules.

Sixteen fields extend the original ten-field row with current Assignment ID/title/state, Study ID/title and Course state. Author UUID identifies existing submitted work without a cross-owner profile lookup. Source answer/instruction and grade versions remain pinned; current labels never rewrite selected Course snapshots/history. No score, reason, answer, grader identity, rubric or files are copied. Selecting an item rechecks current Course binding, then opens exact Study/Assignment/Submission through original freshly authorized reads. Same-Assignment different-author selection remounts source; current answer and original version-checked grading controls are loaded. Explicit grading still requires confirmation/CAS/source checks. No automatic grade or restoration.

GET /api/groups/{groupId}/courses/{courseId}/submissions/grading-queue accepts singleton filter/after/limit only, canonical UUIDv7, empty GET body, registered secure singleton session and no-store. One statement joins only local canonical Course/current curriculum/Study/Assignment/Submission/Grade and exact grade-version Retraction with full source/tenancy/author tuples and authenticated OWNER exclusion. Source and marker share a statement snapshot. Filters precede limit+1 ordered by Submission UUID, default20/max100. Existing curriculum/catalog/Assignment-author/grade-submission/exact marker keys support bounded reads. Pages reflect current reads; refresh starts from the beginning. Removed curriculum links disappear; stale row selection blocks navigation pending refresh. Archived parents retain reads.

Memory-only UI validates exact fields/enums, version/null/marker/source relationships, requested filter, common Course state and ordered bounded cursor. Failed/malformed/wrong-filter reads clear rows/cursor with explicit retry and no false empty result. Refresh/filter preserve an open grade draft and Course edit draft. Hide/unmount aborts/clears; authorization loss clears Group detail. No polling or persistent browser storage. Optional initial Submission source is passed only through the selected matching Study/Assignment; existing navigation without it remains unchanged. Original source API validates all IDs and authority before rendering selected private work.

No cross-owner SQL/FK, persistent ID/revision/Outbox, migration, published Proto, dependency/dataset, enrollment, notification, unread tracking or private progress/sharing mutation. Existing grading writers and self-grading prohibition unchanged. Fixed submission.reads type=course-grading-queue and existing traces/pool/probes apply; no private content logging.
