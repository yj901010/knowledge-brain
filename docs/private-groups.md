# Private Group creation

Registered accounts can open `/graph/groups`, create a PRIVATE Group and browse their own creation requests and immutable creation history. Space assigns the creator an ACTIVE OWNER membership. Group titles and descriptions are literal text; identical titles are allowed and IDs distinguish them. Invitations and membership changes are now documented in group-memberships.md; Study/Course/Assignment/Discussion/Submission and Group content remain subsequent work. Existing Personal-only APIs remain Personal-only.

## Ownership and recovery

Collaboration owns Group configuration, request idempotency and revisions in `brain_collaboration`. Space owns GROUP Space, visibility and membership in `brain_space`. IDs are UUIDv7 generated by their owning service; external IDs have no cross-service FK. There is no shared transaction or cross-database access.

1. Resolve the current REGISTERED principal through Space's dedicated HTTPS capability (Space freshly introspects Identity).
2. In one Collaboration transaction persist a PENDING Group, revision 1 and `GroupCreationRequested` Outbox.
3. Call Space outside the database transaction. Space atomically provisions its own UUIDv7 PRIVATE GROUP Space, OWNER membership, immutable Group reference and `GroupSpaceCreated` Outbox. Group ID replay cannot create another Space or restore retired access.
4. In a Collaboration transaction attach the authorized Space, activate the Group, revision 2 and `GroupActivated` Outbox.

Failure leaves a durable PENDING request. Retry the same `(principal, Idempotency-Key)` and exact settings, or choose **생성 이어가기**. Space provision and Group completion are idempotent under concurrency and process restart. Changing settings with a used key returns 409. An ACTIVE replay produces no new revision/event. An activation Outbox failure rolls back only activation; the provisioned Space remains for forward recovery. No compensation or deletion is required.

No personal notes, learning progress, files or evidence are copied or shared. Group creation alone does not grant Group content APIs or public visibility. UI browser storage contains no credentials or Group data.

## Authorization and pages

HTTPS and exactly one secure browser credential are required. Writes require same Origin and JSON. Gateway exposes only the Group collection, detail, revision and completion routes, never internal capabilities. Collaboration has a dedicated Space credential and no Identity/other service database credential. Guest 403, foreign Group 404; active Groups require fresh PRIVATE GROUP OWNER grant matching both IDs on every read/replay. Session/permission denial clears rendered private data.

List uses owner-scoped UUID keyset candidates (default 20, maximum 100), then one bounded Space authorization batch. `nextAfter` is the last candidate scanned when another candidate exists; revoked rows are filtered so a page may be empty/short with a non-null advancing cursor. No unauthorized title or total is returned. History uses descending revision keyset (default/max 10). Group creation is immutable in this slice; versions are 1=PENDING, 2=ACTIVE.

## Event and operational setup

Immutable Protobuf contracts: `collaboration/group-events/1` → `collaboration.group.v1`, `space/group-space-events/1` → `space.group-space.v1`. Common envelope includes event ID, aggregate, actor, trace and Space once available. PENDING events omit Space, ACTIVE events include it. Changes use local ACID Outbox → Debezium → Kafka; consumers must handle at-least-once delivery. Raw record bytes and trace/schema headers are verified against owning Outbox rows, including unacknowledged replay.

Apply service Helm base plus environment values. Local replicas/pools/resources differ, ownership and communication do not. Provision local TLS/capability using `scripts/Provision-LocalCollaboration.py`; preserve existing keys. Publish contracts using `scripts/Run-GroupContractValidation.py` before writers. Migrate owner DB, then `scripts/Provision-CollaborationCdc.py`, update brain-connect Helm mounts/topics/producer ACLs, and `scripts/Run-CollaborationConnectorConfiguration.py`. Existing Space connector routes `group-space` automatically; do not reset its offsets/slot. New CDC role can SELECT only its Outbox and cannot read Group tables or connect to other owner DBs.

Gateway emits route/status metrics and trace IDs; traceparent propagates through Space/Identity and both Outboxes. Spring HTTP observations and JDBC pool metrics use the existing Actuator facilities; readiness includes owner DB. Trace context is carried explicitly in internal HTTP and Outbox. Full OpenTelemetry exporter/collector/dashboard deployment remains part of the platform observability work, and this slice does not claim that end-to-end tracing stack is already deployed. Registry rules FULL validity and FULL_TRANSITIVE compatibility; no previously published contract is changed. No new runtime library/version/dataset; reused JDBC/Flyway/Hikari/Protobuf/Jib dependencies have the existing license review in dependency-licenses.md.

Local validation and deployment evidence is recorded in `.local/groups-validation.json` after completion.

Member participation uses separate APIs without broadening these OWNER-only creation endpoints: [group-memberships.md](group-memberships.md).
