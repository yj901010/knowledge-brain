# 숫자·날짜 속성 범위 검색

`/graph`의 **내 노트 목록 → 속성 탐색 열기 → 속성 선택**에서 숫자 또는 날짜를
고르고 **조건 방식: 범위**로 전환한다. 최솟값과 최댓값을 입력한 뒤
**값 조건 적용**을 누르면 두 경계를 포함하는 활성 노트를 조회한다.

- `점수 80 이상 · 100 이하`, `날짜 2024-02-29 이상 · 2024-03-01 이하`처럼 사용한다.
- 한쪽을 비우면 그 방향에 제한이 없다. 두 입력을 모두 비우면 오류를 안내한다.
- 최솟값과 최댓값이 같아도 유효하다. 숫자 `8e1`과 `80.00`은 같은 경계이다.
- 음수와 0, 기존 최대 정밀도의 소수를 지원한다. 날짜는 실제 달력 날짜로 비교한다.
- 문자열·참/거짓·문자열 목록은 기존 정확한 값 조건을 사용한다.

[태그 조건](property-tag.md)과 함께 적용해 두 조건을 모두 만족하는 노트를 찾을 수 있다.

입력이나 조건 방식만 바꿔서는 적용된 조건이 바뀌지 않는다. 잘못된 범위를 적용하면
현재 결과를 유지한다. 다음 페이지와 새로고침은 적용된 조건을 유지하며,
**값 조건 해제**는 전체 값과 정확한 값 입력 방식으로 돌아간다. 속성 선택 변경·해제와
패널 닫기에서는 입력과 적용 조건을 초기화한다. 노트 편집 초안은 탐색과 독립적이다.

필터는 전체 활성 노트에 적용한 뒤 생성 ID 순서로 페이지를 나눈다. 속성 목록의
개수는 조건 적용 전 전체 활성 노트 수이다. 고정 snapshot이나 일치 개수 집계는 아니다.
범위를 벗어나는 응답 값, 잘못된 응답이나 조회 실패는 결과를 비우고 새로고침을
안내한다. 늦은 이전 조건 응답은 버린다. 접근 철회는 기존 개인 화면 초기화 경로를
사용하며 조건이나 노트 목록을 브라우저 저장소에 저장하지 않는다.

## API와 소유권

`GET /api/spaces/{spaceId}/property-definitions/{propertyId}/notes`에 선택적
`minValue`, `maxValue` query를 추가한다. NUMBER와 DATE만 지원하며 각 경계는
포함된다. `value` 정확 일치 조건과 범위 조건을 함께 보낼 수 없다.

```text
?minValue=80&maxValue=100&limit=20
?maxValue=2024-02-29
?minValue=-10&maxValue=0&after=<UUIDv7>
```

생략한 경계는 제한이 없다. 빈 경계, 뒤집힌 범위, 지원하지 않는 속성 타입,
잘못된 값, 중복·알 수 없는 키와 혼합 조건은 400이다. 숫자는 JSON 숫자 문법,
최대 원문 96자·지수 3자리, 정규화 후 유효숫자 38자리·소수부 18자리·정수부 56자리
제한을 사용한다. 날짜는 유효한 `YYYY-MM-DD`이다. 각 query 값은 최대 200 Unicode
code point이며 올바른 UTF-8과 NUL 금지 규칙을 따른다.

응답 형식, `after` UUIDv7 커서, `limit` 기본 20·최대 100과 `Cache-Control: no-store`는
기존과 같다. 다음 페이지에도 같은 경계를 보내야 한다. 매 페이지 Space 권한을
새로 확인하고 PRIVATE/ACTIVE Note만 조회한다. 다른 Space나 미등록 속성은 404이다.
조회 요청 본문과 쓰기 메서드는 Gateway에서 거절한다.

AGENTS.md와 PROJECT.md의 소유권·아키텍처 결정과 충돌하지 않는다. Content 소유
PostgreSQL의 고정 타입 JSONB 값을 parameter binding으로 `>=`, `<=` 비교하고
커서·LIMIT 전에 적용한다. 날짜 문자열은 고정된 ISO 형식의 순서로 비교한다.
화면은 소수 값을 부동소수점으로 변환하지 않고 부호·십진 자릿수로 검증한다.
기존 V13 조회 인덱스와 `brain.content.metadata.reads{type=property_notes_filtered}`
카운터를 사용한다. 새 migration·의존성·이벤트나 정본 데이터 변환은 없다.

## 검증

실제 PostgreSQL/Kafka와 Gateway에서 포함 경계·단일 경계·음수·0·정밀 소수·날짜,
20+2 페이지, 다른 Space 차단, 폐기·연결 해제 제외와 읽기 부작용 없음을 확인한다.
로컬 Kubernetes 브라우저에서 조건 초안·편집 초안 유지, 잘못된 범위, 모바일 폭,
조건 전환·해제, 응답 불일치·지연·실패 복구와 접근 철회를 확인한다.
기존 정확 일치·속성·태그 탐색과 메타데이터·목록·폐기 회귀를 함께 수행한다.
실행 결과는 [검증 기록](property-range-validation.txt)에 기록한다.
