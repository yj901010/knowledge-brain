# Group-wide own resubmission requests

On /graph/groups, each current registered Group participant opens Group -> 그룹 내 재제출 요청 열기. The collapsed memory-only overview lists only existing requests on the freshly authenticated actor submitted work across all canonical Studies in the exact Group/Space, including standalone Studies without Course bindings. Independent of enrollment/private progress. OWNER receives only own requests here, including existing permitted OWNER own-request review. VIEWER reads own requests with original write restrictions. Current Space participation and matching ACTIVE Collaboration Group configuration precede SQL; removed participants lose access.

REQUESTED default; ALL, RESOLVED, CANCELLED, UNAVAILABLE retain Study/Course semantics. REQUESTED requires requested answer=current answer and no resolved answer. CANCELLED requires requested answer<=current and no resolved answer. RESOLVED requires requested<resolved<=current answer; subsequent answers never move the pinned resolved version. Unknown/missing/inconsistent metadata becomes UNAVAILABLE, never pending/resolved. Idempotent replay of an older submission never resolves a newer request. Resolution means newer answer arrival, never grading, passing or private completion. Source writers own atomic resolution; overview reads do not resolve or cancel requests.

Fourteen fields: Submission ID/version/submitted Assignment version/update time, request version/state/requested and resolved submission versions, current Assignment ID/title/state and current Study ID/title/state. No author ID, peer roster/count, unrequested or unsubmitted rows, reason, answer, score or file copies. Current labels preserve submitted instruction versions. DRAFT/CLOSED/RETIRED source reads remain available under existing rules, with pending requests retained even when submission is blocked. Mixed Study lifecycle states are valid; Study completion is separate from private Learning completion.

GET /api/groups/{groupId}/my-resubmission-requests accepts singleton filter/after/limit, canonical UUIDv7, empty GET body, secure singleton registered session and no-store. Ascending Submission UUID keyset/default20/max100, predicates before limit+1. One Collaboration-owned SQL statement joins own-author Submission/Assignment/Study and existing Request with full Group/Space/Study/Assignment/author scope. Current answer and requested/resolved versions share a statement snapshot. Existing local indexes are reused. No Course query, cross-owner SQL/FK, new persistent IDs/revision/Outbox, migrations, published Proto or dependencies/datasets.

Explicit selection rechecks participation, then remounts exact original Study/Assignment using the fresh OWNER flag. Original source APIs supply private reason/answer, current request/version state and current CAS/confirmation/idempotency/submit authority. Same-Study different-Assignment, cross-Study and repeat selection load fresh original sources. Overview refresh/filter preserve open answer and Study edit drafts. Source close, Group switch, hidden tab/unmount and authority loss clear target. Both owned and participating Group entry points share the workspace. A newly changed VIEWER role receives readonly source controls and original submit API403.
