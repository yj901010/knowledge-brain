# GitHub completed sync history

In a registered personal Space, open a GitHub connection, then **GitHub 커밋 동기화 이력 열기**. Each completed observation shows confirmation time, repository version, scanned/imported counts and observed head SHA. Successful zero-import runs and empty repository observations are included. A browser reply can be lost after a server commit; its completed receipt still exists. Failed attempts are not turned into success history. Counts do not imply full Git history, platform-user contribution, ownership or learning completion.

This read-only follow-up uses Integration's existing immutable github_sync snapshots. No new canonical tables, migrations, dependencies, event contracts, projections, CDC privileges, authentication scope or privacy decisions are introduced. Existing connect/sync/disconnect commands and byte contracts remain unchanged. Reads do not call GitHub, change the repository version, create receipts/revisions/Outbox entries, import commits or update Activity/progress. Disconnected repositories retain history under the same current registered PRIVATE PERSONAL OWNER authority. Guest access is403; unknown/foreign repository or Space404; unavailable identity/Space/storage503.

GET `/api/spaces/{spaceId}/github/repositories/{repositoryId}/syncs` accepts only singleton optional positive `before` and `limit` (default20/max100), with an empty body. It returns `{items,nextBefore}`; items contain the existing eight receipt fields only. Request key, request actor, expected version, credential and failure contents are never returned. Ordering uses persisted expected_version descending, corresponding to repositoryVersion in the receipt, so equal timestamps and disconnect-version gaps are safe. `before` is exclusive repositoryVersion. One look-ahead row determines nextBefore; null means no older rows. A concurrent newer observation does not enter the next older page; refresh starts at current newest. Every page checks current Space authority and exact repository/Space scope. Responses/errors are no-store.

The independent UI loads20 per page and validates scope, IDs, eight-field shape, logical order, duplicate IDs, counters, head SHA, possiblyMore and cursor before rendering. Failed or malformed reads clear stale rows and offer explicit refresh. Close, hiding, repository reselect, parent-version change, Space switch and logout discard pending responses and local history. Existing connect URL drafts and consent remain independent. No polling, browser persistence or automatic retry. The existing bounded counter brain.integration.github.reads adds the fixed sync-history type.

Validation uses real PostgreSQL for exact immutable snapshots, replay/failed-command exclusion, equal-time logical paging, concurrent new observations, retirement retention, scope isolation and no read mutations. API/Gateway tests cover fresh authority, exact paths/methods and strict inputs without remote calls. Browser checks combine real public GitHub imports and history with explicitly synthetic response fixtures for paging/malformed/late response boundaries; the latter do not create sync records. Existing GitHub behavior, Activity and Group workflows are regression checked. See github-sync-history-validation.txt for final run evidence.
