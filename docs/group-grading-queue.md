# OWNER Group-wide grading queue

On /graph/groups, current OWNER opens Group -> 그룹 채점 대기 목록 열기. This collapsed memory-only queue includes other authors submitted work across all Studies/Assignments in the same Group/Space, including standalone Studies without Course relationships. OWNER own work stays excluded under no-self-grading. No non-submitter roster, Course binding, enrollment or private progress requirement. Fresh current registered Space OWNER authority and matching ACTIVE Collaboration Group configuration precede queue SQL on every request. MEMBER/VIEWER403 even for empty queues; removed participation loses access.

NEEDS_GRADING default includes all except CURRENT. ALL, MISSING, CURRENT, OUTDATED, RETRACTED and UNAVAILABLE preserve existing exact latest grade-version semantics. Direct/rubric0 count. Historical markers never mark newer grades. A grade on an older answer stays OUTDATED even if withdrawn. Unknown/missing marker state or future source becomes UNAVAILABLE, never current. Metadata is not passing/completion or write eligibility. Archived Study/Assignment definitions retain reads with original source write restrictions.

Sixteen fields: original Submission/author/source/time and grade status/version/source/exact annotation metadata, current Assignment ID/title/state, current Study ID/title/state. Original submitted instructions remain pinned. No answer, score, reason, grader identity, rubric or file copies. Independent queue refresh/filter preserve open grade and Study edit drafts. Explicit row selection rechecks current Group OWNER and remounts the existing exact original Study/Assignment/Submission flow, including same-Assignment different-author, cross-Assignment and cross-Study selection. Source close, Group switch, hidden tab/unmount or authority loss clear the target. Both owned-Group and participating-OWNER entry points use the same workspace; MEMBER/VIEWER do not render it. Existing Study/Course panels and source writers remain unchanged.

GET /api/groups/{groupId}/submissions/grading-queue accepts singleton filter/after/limit only, canonical UUIDv7, empty GET body, default20/max100, registered secure singleton session and no-store. Local ACTIVE Group/Space check followed by one local canonical Study/Assignment/Submission/Grade/exact grade-version Retraction metadata statement using full tenancy/source/author tuples and authenticated OWNER exclusion. Source and annotation share one snapshot. Existing Group/Study/Assignment catalog, Assignment-author, grade-submission and marker keys are reused. Predicates precede limit+1 and ascending Submission UUID keyset; pages reflect current reads and refresh begins at the start. No Course/curriculum/enrollment query or cross-owner SQL/FK.

UI validates exact sixteen fields, enums, nullable/source/marker relationships, requested filter and bounded ordered cursor. Study states may differ across rows because the queue spans Studies. Invalid/error responses clear rows/cursor with explicit retry and no false empty result. Hidden/unmounted views abort/clear; authority loss clears parent Group. No polling or persistent browser storage. Fresh role check and original source APIs remain authoritative for all commands.

No new persistent ID/revision/Outbox, migration, published Proto, dependency/dataset, Course creation, enrollment, notification, unread tracking or private progress/sharing mutation. Fixed submission.reads type=group-grading-queue and existing traces/pool/probes apply without private content logging. This packages existing OWNER submitted-work read rights without restructuring service boundaries or changing source policy.

OpenAPI: contracts/openapi/group-grading-queue.yaml. API/Gateway tests cover current OWNER and strict role/session/query/body/path behavior. Browser proof covers real grading and source reselection, multiple Study states, Group switching, fresh-role failure, drafts, recovery/privacy/mobile and existing queue/source regressions.
