# OWNER Study grading queue

On /graph/groups, current OWNER opens Group -> Study -> 스터디 채점 대기 목록 열기. The collapsed queue spans all assignments in one Study, including standalone Studies with no Course relationship. Only other authors submitted work appears; OWNER own work remains excluded under no-self-grading. No non-submitter roster, obligation, enrollment or private progress is inferred. Every request freshly checks registered Space OWNER authority before the local database. MEMBER/VIEWER403 even for empty queues; removed participation loses Group access. Existing Course/Assignment queues and own views retain exact APIs and behavior.

NEEDS_GRADING default includes all except CURRENT. ALL, MISSING, CURRENT, OUTDATED, RETRACTED and UNAVAILABLE retain original grading semantics. Grade0, direct or rubric, counts as a record. Exact latest grade-version annotations apply only to that grade; historical markers cannot mark newer grades. A grade targeting an older answer stays OUTDATED even if withdrawn. Unknown/missing marker state or future source is UNAVAILABLE, never current. Metadata never means passing, verification, completion or write eligibility. Archived Study/Assignment records retain reads with original grade restrictions.

Fourteen metadata fields extend the original ten-field Assignment grading row with current Assignment ID/title/state and Study state. Original submitted instruction/answer and grade-source versions remain pinned. No score, reason, answer, grader identity, rubric or file contents. Selecting an item refreshes current Study context and opens exact Assignment/Submission through existing freshly authorized reads and confirmed CAS grading controls. Same-Assignment author changes and cross-Assignment selections remount source, leaving original writers unchanged. Independent refresh/filter preserve an open grade draft and Study edit draft. Explicit Study changes discard the previous target; incoming Course source pointers still pass through when no Study queue target is chosen.

GET /api/groups/{groupId}/studies/{studyId}/submissions/grading-queue accepts singleton filter/after/limit only, canonical UUIDv7, empty GET body, default20/max100, registered secure singleton cookie and no-store. A single local statement joins canonical Study/Assignment/Submission/Grade/exact grade-version Retraction with full tenancy/source/author tuples and authenticated OWNER exclusion. Source and annotation share a snapshot. Existing Study/Assignment catalog, Assignment-author, grade-submission and marker keys support bounded reads; predicates precede limit+1 and ascending Submission UUID keyset. Pages reflect current reads; refresh begins at the start. No Course/curriculum/enrollment query or requirement.

Memory-only UI validates exact fourteen fields/enums, nullable/source/marker relationships, requested filter, common Study state and bounded ordered cursor. Invalid/error reads clear rows/cursor with explicit retry and no false empty result. Hide/unmount aborts/clears; authority loss clears Group details. No polling or persistent browser storage. Source context always uses matching selected Study; backend exact Assignment/Submission scope remains authoritative. No cross-owner SQL/FK, new persistent ID/revision/Outbox, migration, published Proto, dependency/dataset, Course creation, enrollment, unread tracking, notification or private progress/sharing mutation. Fixed submission.reads type=study-grading-queue and existing traces/pool/probes apply without private text logging.
