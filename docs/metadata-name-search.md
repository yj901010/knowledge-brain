# 태그·속성 이름 검색

`/graph`의 **내 노트 목록 → 태그 탐색 열기** 또는 **속성 탐색 열기**에서 이름 일부를
입력하고 **이름 검색**을 누른다. 속성의 **태그 조건 고르기** 안에서도 태그 이름을
검색해 조합 조건으로 선택할 수 있다. 전체 정의에 검색 조건을 적용한 뒤 20개씩
불러오므로 첫 페이지에 없는 항목도 찾을 수 있다.

검색은 대소문자와 공백을 구분하는 부분 일치이다. 앞뒤 공백을 제거하지 않으며
공백만으로도 이름에 공백이 있는 항목을 찾을 수 있다. `%`, `_`, 따옴표 등은 문자
자체이다. Unicode는 NFC로 정규화하므로 조합 형태가 다른 같은 글자를 찾을 수 있다.
검색어는 정규화 후 1~64자이며 입력 원문은 최대 128 Unicode code point이다.
빈 입력과 제어 문자는 거절한다. **이름 검색 해제**로 전체 목록을 다시 조회한다.

입력 중인 검색어를 바꾸기만 해서는 결과가 바뀌지 않는다. 다음 페이지와 새로고침은
적용된 검색어를 유지한다. 태그·속성 목록 검색을 새로 적용하거나 해제하면 기존
항목 선택과 그 상세 목록을 닫는다. 노트 편집 초안은 유지한다. 조합 검색의 태그
선택기에서 이름 검색을 바꾸면 태그 선택 초안만 지우며 적용한 태그와 값 조건,
노트 결과는 유지한다. 탐색이나 선택기를 닫으면 그 이름 검색을 초기화한다.

미사용 정의도 검색 결과에 남고 활성 노트 개수는 0으로 표시한다. 결과가 없으면
검색 결과가 없다는 안내를 보여 준다. 잘못된 검색어는 기존 결과를 유지하며,
조회 실패나 검색어와 맞지 않는 응답은 해당 목록을 비우고 새로고침을 안내한다.
이전 검색의 늦은 응답은 버린다. 접근 철회는 개인 화면을 초기화한다.
목록·검색어는 브라우저 저장소에 쓰지 않고 탐색 중 도메인 데이터를 변경하지 않는다.

## API와 기존 결정

다음 두 경로에만 선택적 `q` query를 추가한다.

- `GET /api/spaces/{spaceId}/tags?q=study`
- `GET /api/spaces/{spaceId}/property-definitions?q=score`

`q` 생략은 기존 전체 목록이다. 빈 `q`, 중복·알 수 없는 query key, 잘못된 Unicode와
제어 문자는 400이다. 원문 최대 128자·NFC 정규화 후 1~64자를 검사한다. 값은 UTF-8
URL encoding으로 전송하며 Gateway는 총 query 길이 1700자를 제한한다. 태그별·속성별
노트 조회 경로에 `q`를 보낼 수 없다. 본문 검색 API의 `q`와는 별개의 이름 조건이다.

응답 `{items,nextAfter}`와 각 정의의 `{id,name,type,activeNoteCount}`는 유지한다.
`after` UUIDv7 커서, `limit` 기본 20·최대 100, 현재 Space 권한 확인과
`Cache-Control: no-store` 규칙도 같다. 다음 페이지에도 같은 `q`를 보내야 한다.
다른 Space의 목록은 조회할 수 없으며 조회 본문과 쓰기 메서드는 허용하지 않는다.

AGENTS.md와 PROJECT.md의 결정과 충돌하지 않는다. Content가 소유한 PostgreSQL에서
`position(? in d.name)>0`과 바인딩한 문자열로 커서·LIMIT 전에 적용한다. SQL wildcard나
정규식·본문 검색을 실행하지 않는다. 기존 정의와 Note lifecycle·사용 개수를 유지한다.
새 migration·dependency·이벤트나 정본 변환은 없다. 기존 HTTP/trace 관측과
`brain.content.metadata.reads{type=tags_filtered|property_definitions_filtered}`를 사용하고
검색어·도메인 ID를 metric label에 넣지 않는다.

## 검증

실제 PostgreSQL/Kafka와 Gateway에서 두 목록의 20+2 페이지, 미사용 정의 유지,
대소문자·공백·특수 문자·NFC·최대 길이, 다른 Space 차단과 읽기 부작용 없음을 확인한다.
로컬 Kubernetes 브라우저에서 세 검색 화면, 검색 초안·편집 초안 유지, 조합 조건 유지,
해제·새로고침·실패 복구·잘못된 응답·지연과 접근 철회를 확인한다.
기존 태그·속성·값·범위·조합·메타데이터·노트 목록·폐기 회귀를 함께 수행한다.
실행 결과는 [검증 기록](metadata-name-search-validation.txt)에 기록한다.
