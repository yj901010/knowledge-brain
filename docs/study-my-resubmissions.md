# Study own resubmission requests

On /graph/groups, open Group -> Study -> 스터디 과제 -> 내 재제출 요청 열기. Current registered OWNER/MEMBER/VIEWER see only existing requests attached to their own submitted work across this Study. OWNER sees only own work here. No-request submissions, peers, non-submitters or roster counts are absent. Existing own submission/grade overview and OWNER queues retain their endpoints, exact response shapes and filter vocabulary.

REQUESTED is the default filter; ALL, RESOLVED, CANCELLED and UNAVAILABLE are explicit alternatives. One current request per submitted aggregate; this is not a request revision export. Eleven metadata fields contain submission/assignment IDs, current shared Assignment title/state, latest submitted version and its original instruction version/time, request version/state, requested answer version and optional resolving answer version. No reason, answer, request actor, score, rubric, file or private Note is copied. Reasons and full immutable request history remain in original authorized submission detail.

REQUESTED must target the current answer and have no resolution. CANCELLED retains its original target, possibly older than the latest answer, with no resolving version. RESOLVED requires requestedVersion < resolvedVersion <= currentAnswerVersion; later answers never rewrite that first resolution. Unknown/missing state or inconsistent source metadata is UNAVAILABLE, never pending/resolved. Resolution means a new answer arrived; it does not grade or complete learning. A closed/archived Assignment can retain pending requests; the overview never reopens submissions. The original current-source component supplies fresh submission eligibility after row selection.

GET /api/groups/{groupId}/studies/{studyId}/my-resubmission-requests accepts only singleton filter/after/limit, default20/max100, canonical UUIDv7, no GET body, secure registered singleton session and no-store. Space freshly authorizes Group participation before Collaboration reads. Current VIEWER retains own history; removed participants lose access. Caller author selectors are rejected. One statement joins only local Assignment/Submission/ResubmissionRequest canonical metadata with full Group/Space/Study/Assignment/author tuples, applies the actor predicate and filter before limit+1, and orders by Submission UUID. Existing Study/Assignment catalog, Assignment/author and request/submission unique indexes support the lookup. Pages reflect current reads; refresh begins from the start. No cross-owner SQL/FK, mutation, new persistent ID/revision/Outbox, migration, event contract, dependency/dataset, notification or private progress change. Existing fixed-label submission.reads type=study-mine-requests, pool/probes and traces apply; private text is absent from metrics/logs.

Collapsed memory-only UI validates exact fields, version/null/state relationships, requested filter and bounded ordered cursor. Failed or invalid reads clear rows/cursor, preserve open answer drafts and offer explicit retry without a false empty message. Filter/refresh do not replace source detail. Selecting an item explicitly opens the original Assignment, reloads own current answer and request, and rechecks source write rules. Hide/unmount aborts and clears state; denial clears participant Group details. No polling or persistent browser storage.

OpenAPI: contracts/openapi/study-my-resubmissions.yaml.
