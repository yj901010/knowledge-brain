# OWNER Course feedback and request review queue

On /graph/groups, current OWNER opens Group -> Course -> 코스 피드백·재제출 검토목록 열기. The collapsed memory-only queue includes submitted work in current canonical Course curriculum, independently of enrollment/private progress. Existing OWNER own-submission feedback/request workflows are included. The separate grading queue and writer still forbid self-grading. No non-submitter roster or profile lookup. MEMBER/VIEWER403 even for an empty queue; removed participation loses Group access. Current Space registered OWNER authority precedes the database on every request.

NEEDS_FEEDBACK is default: missing, older-answer, exact latest withdrawn or unavailable feedback. HAS_FEEDBACK requires known current-answer latest feedback and absent/restored annotation. RETRACTED_FEEDBACK includes explicit exact latest-version withdrawal on current or older answer, excluding unavailable feedback. Historical markers never mark newer comments. PENDING_RESUBMISSION is independent: current requested answer with no resolution. CANCELLED retains its original source without resolving version; RESOLVED requires requested < resolved <= current answer. Later answers preserve first resolution; old replay cannot resolve a later request. Unknown/missing/inconsistent metadata becomes UNAVAILABLE, never current feedback or a pending/resolved request. UNAVAILABLE filter includes either unsafe dimension; known current feedback can still coexist with an unavailable request. ALL includes all submitted rows. Source metadata never means grading, approval or learning completion.

Twenty fields: Submission/author/source versions/time; normalized feedback status/version/source and exact latest-version marker/state/version; needsFeedback; request version/state/source; current Assignment ID/title/state, Study ID/title and Course state. Current labels preserve original submitted instructions and selected Course snapshots/history. No answer, comment, request/withdrawal reason, score, rubric or file contents. Explicit selection freshly verifies Course binding and exact original Study/Assignment/Submission authority; existing source controls read text/history and retain confirmation/CAS/source guards for commands. Same-Assignment different-author and cross-Study selections open fresh source. List refresh/filter preserve feedback/request and Course edit drafts. Archives retain source reads and existing write restrictions; pending requests never reopen submissions.

GET /api/groups/{groupId}/courses/{courseId}/submissions/review-queue accepts singleton filter/after/limit, canonical UUIDv7, empty GET body, default20/max100, secure registered singleton session and no-store. One statement joins only local canonical Course/current curriculum/Study/Assignment/Submission/Feedback/exact feedback-version Retraction/Request using full tenancy/source/author tuples. Source feedback and atomic request resolution share a snapshot. Existing curriculum/catalog/Assignment-author/feedback-submission/marker/request unique keys support bounded reads; predicates precede limit+1 and ascending Submission UUID. Pages reflect current reads; refresh starts from the beginning. Removed links disappear, stale source navigation blocks until refresh. Source APIs retain text and command authority.

UI validates exact twenty fields, enums, nullable versions, feedback classification/needs relationship, normalized request source ranges, requested filter, common Course state and bounded ordered cursor. Invalid/error responses clear rows/cursor, show explicit retry and no false empty result. Hide/unmount aborts/clears; authorization loss clears Group detail. No polling or persistent browser storage. Existing per-Assignment review API retains its published twelve fields, five filters and ALL default. UNAVAILABLE is added only to this separate Course route. Existing grading and own overviews stay unchanged.

No cross-owner SQL/FK, persistent ID/revision/Outbox, migration, published Proto, dependency/dataset, enrollment, notification, unread tracking or private progress/sharing mutation. Fixed submission.reads type=course-review-queue, existing traces/pool/probes, no private content logging. This extends existing OWNER submitted-work read rights without changing architecture or source writers.
